# 教学工作流细则

> SKILL.md 的 Step 1~7 在这里展开。每节都对应 SKILL.md 的某一条硬条款，改动前先回去看那条。

---

## 1. 需求澄清：什么时候问，什么时候假设

### 1.1 必须明确的字段

| 字段 | 示例 | 缺失时 |
|---|---|---|
| **学习主题** | Attention、一点透视、二分查找 | **必须明确**，否则无法开始 |
| **当前先验** | 会 Python，不懂线代 | 可用一句诊断题推断，别问「你什么水平」——人说不准自己 |
| 学习目标 | 能解释原理 / 能实现 / 能过面试 | 优先明确，缺失时按「能解释 + 能判对错」默认 |
| 可用时间 | 20 分钟 / 一整个下午 | 缺失时用明确标注的默认值，别偷偷省略 |
| 语言 | 中文 | 跟随用户语言 |
| 特殊约束 | 少公式 / 重代码 / 手机上看 | 有则遵守，无则不假设 |

### 1.2 澄清的红线

**只在「缺了它会明显改变课程形态」时才追问。** 判断方法：把缺失信息填两个极端值，课程会不会变成两节完全不同的课？

- 「20 分钟还是 3 小时」→ 会。演示数从 7 个砍到 2 个。**值得问。**
- 「用中文还是英文」→ 用户已经在说中文了。**不问。**
- 「你想先学 Q 还是先学 K」→ 这是教学内容，你不该把决策丢回去。**不问。**

其余情况一律采用合理假设，**并在课程开头写明假设**：「本课假设你会写 Python 但不熟悉矩阵，若不符请告知调整」。

### 1.3 一句诊断题的写法

比问「你什么水平」有效得多：

> 「`[1, 2, 3]` 和 `[4, 5, 6]` 相乘，你直觉上是得到一个数还是一个向量？」

- 答「两个都能说清」→ 有领域基础
- 答「一个向量」或「逐项乘」→ 有编程基础
- 答「不知道 / 没学过向量」→ 零基础

一句话定档，比三句话的问卷准喵。

## 2. Step 2 细则：把目标写成可验证的一句话

### 2.1 三档动词

| 档 | 动词 | 例子 | 可验证性 |
|---|---|---|---|
| ❌ 不可验证 | 了解、熟悉、掌握、理解 | 「理解注意力机制」 | 无法出题 |
| ⚠️ 弱可验证 | 说出、列举、复述 | 「说出注意力三个矩阵的名字」 | 能测记忆，测不出应用 |
| ✅ 可验证 | 算出、判断、补全、找出、预测 | 「手算 3 个词的注意力权重，且每行和为 1」 | 能测应用与迁移 |

### 2.2 目标必须与练习一一对应

写完目标后立即写：**哪道题、哪个演示会检查它？**

```
目标：能手算 3 个词的注意力权重，且每行和为 1
─ 检查点 1：演示④ 让用户手算第 3 个词的权重，并核对每行和
─ 检查点 2：自测第 6 题（迁移题，换成 5 个词）
```

对不上的目标 → 要么删掉目标，要么补练习。**不允许目标挂在开头然后后面不管**，那是装饰。

### 2.3 目标数量的上限

一节 20~40 分钟的课，**最多 3 个目标**。写 5 个说明这一节其实是三节课。

一节课只有一个目标也完全正常，而且往往效果更好。

## 3. Step 3 细则：卡点清单（本流程最容易做错的一步）

### 3.1 知识点清单 vs 卡点清单

| | 知识点清单 | 卡点清单 |
|---|---|---|
| 长什么样 | 「向量、点积、softmax、注意力权重」 | 「读到『形状是 152064×3584』会停住，因为他不知道形状是行话」 |
| 产出 | 目录 | 课的骨架 |
| 用户感受 | 又一个提纲 | 一句一句被接住 |

**列知识点 = 写大纲；列卡点 = 写课。** 这两件事的差别就是课能不能用的差别。

### 3.2 卡点清单模板

```markdown
| # | 卡点原文 | 停住的原因 | 缺的前置概念 | 他能自己推出来吗 | 先给什么 |
|---|---|---|---|---|---|
| 1 | 「形状是 152064 × 3584」 | 不知道「形状」是行话 | 矩阵 = 几行几列的数字表 | 不能 | 先说「形状就是几行几列」，配 Excel 类比 |
| 2 | 「拿向量去乘一堆矩阵」 | 不知道矩阵乘向量在算什么 | 加权求和 | 部分能（会算平均） | 从「按比例混合」切入 |
| 3 | 「Q·Kᵀ 为什么表示相关性」 | 不知道点积和夹角的关系 | 点积 = 投影长度 | 不能 | 先给箭头夹角演示 |
```

### 3.3 怎么找卡点（三个可操作的招式）

**招式一：读自己的草稿，标出每个「显然」**
写到「显然」「不难看出」「直接可得」的地方，那后面八成就藏着一个卡点。**你的「显然」就是别人的墙。**

**招式二：倒推前置链**
概念 X 需要 A，A 需要 B。一直推到「他一定会的东西」为止，中间每一环都是一个卡点。

```
注意力权重 ← softmax ← 指数函数 ← 幂运算（他一定会）  ← 3 个卡点
```

**招式三：找真实误解**
去搜这个知识点的常见错误说法。**别人的误解就是你最好的卡点清单**——他们已经替你把坑踩过了。

### 3.4 卡点要排序，不是罗列

按「阻塞程度」排：**不解决它，后面全看不懂**的排最前。

顺序错了的典型症状：讲了半天 softmax，用户还在纠「向量是什么」——你白讲了。

### 3.5 砍卡点

卡点清单通常是最终需求的 2 倍长。砍法：

- **能一句话带过的，不单独开一站**：附在类比里顺带解释
- **本节目标不涉及的，砍掉**：放到「下一站」
- **需要另一节才能讲清的，砍掉**：标成前置课程

砍到剩 **5~7 个**，就是一节 40 分钟课的量。

## 4. 课程蓝图（生成 HTML 前必须先写）

蓝图是**文本**，不是网页。写蓝图的时间大约占全流程 20%，但它决定了另外 80% 是不是白干。

```markdown
## 课程蓝图

**主题**：Transformer 的注意力机制
**先验档位**：零基础（会四则运算，不知道向量）
**本节目标**（≤3 条，可验证）：
  1. 能手算 3 个词的注意力权重，且每行和为 1
  2. 能说出为什么要除以 √d
**必要前置**：乘法、指数、平均值的直觉
**核心概念**（不超过 5 个）：点积、softmax、缩放、QKV、掩码
**卡点清单**：见上表
**交互活动**：
  | 站 | 演示 | 教学目的 | 用户能改什么 |
  |---|---|---|---|
  | 1 | 点积箭头 | 看见「像不像」本质是角度 | 拖角度 |
  | 2 | softmax 温度 | 看见极端化过程 | 拖温度 |
**练习与评分**：
  | 题号 | 类型 | 检查哪个目标 | 反馈可信度 |
  |---|---|---|---|
  | 1~5 | 客观校验 | 目标 1 | 确定 |
  | 6 | 迁移题 | 目标 1+2 | 确定 |
**参考来源**：（联网时）论文/文档；未联网时写「参数化知识，未核验」
**简化假设与限制**：
  - 演示用 d=4，真实模型 d=3584
  - 不涉及多头拼接的完整推导
```

**蓝图不通过就不要动手写 HTML。** 蓝图里想不清「这个演示教什么」，写出来的就是装饰。

## 5. Step 4 细则：选演示的四级优先级

完整对照表见 `interaction-patterns.md`。这里只给判断口诀：

> **能算就别画，能拖就别讲，能动就别静，能静就别编。**

- 能真算 → 做计算器（用户乱填也有对答案）
- 不能算但能对比 → 做滑块看极端
- 不能对比但有序 → 做分步走
- 什么都没有 → **老老实实做一张好表格**，别硬塞动画

**硬塞动画是负分。** 一个与目标无关的旋转立方体，会让用户记住立方体、忘掉概念。

## 6. Step 5 细则：推导四句的写法

### 6.1 标准模板

```
[现象]   你会看到 X。
[为什么] 因为 A → B → C。
[所以]   于是就有了 Y 这个做法。
[不这样] 假如不这么做，会变成 Z（通常更糟）。
```

### 6.2 实例（为什么除 √d）

> **现象**：d 从 4 加到 1024，不缩放时最高权重从 55% 一路涨到 100%——注意力全给一个词，其余全 0。
>
> **为什么**：点积是 d 个数相乘再相加。每个数独立随机的话，和的方差随 d 线性增长，标准差随 √d 增长。d 变 4 倍，分数波动就变 2 倍。
>
> **所以**：分数除以 √d，把标准差拉回 1。这样 d 变多大，softmax 的「尖锐程度」都稳定在同一水平。
>
> **不这样**：不除就会随模型变宽而越来越尖，梯度被压死，训练不动。这是原论文必须加这一项的原因。

四句拆开看：**现象让人不信你瞎编，为什么让人能自己推一遍，所以给出做法，不这样给出代价**。

### 6.3 常见的三种破法

| 破法 | 长什么样 | 怎么修 |
|---|---|---|
| 只给「所以」 | 「所以要除以 √d」 | 补现象 + 为什么 |
| 用「因为显然」代替推理 | 「因为维度大了显然要缩放」 | 换成方差/标准差的定量推导 |
| 省掉反例 | 讲到做法就收 | 补「不这样做会怎样」——**这句最常被漏，也最保命** |

### 6.4 术语首现必拆

任何术语第一次出现，当场拆，**不许留到「以后再讲」**：

```
❌ 「Token 的嵌入向量维度是 d_model」
✅ 「Token（一段文字被切成的最小单位，可能是一个字、半个词、或一个标点）
   的嵌入向量（给每个 Token 配的一串数字，用来表示它的『含义』）
   维度是 d_model（这串数字有几个，比如 3584 个）」
```

面向零基础时，连「形状」「参数」「向量」都要拆。**没拆的术语 = 断掉的台阶。**

## 7. Step 6 细则：自测题的设计

### 7.1 数量与配比

| 档位 | 题数 | 其中迁移题 |
|---|---|---|
| 零基础 | 8~10 | ≥1 |
| 有编程基础 | 6~8 | ≥1 |
| 有领域基础 | 4~6 | ≥1 |

**每 1~2 个概念配 1 题。** 一个概念配 5 题 = 在考记忆，不在考理解。

### 7.2 答后展开的交互规则

```
用户点选项
  ├─ 答对 → 只显示一行确认 + 一句「为什么对」
  └─ 答错 → 自动展开要点（含正确推导链），并指出「你可能是这样想的」
```

**任何情况下都不在答题前显示答案。** 见 `assessment-guidelines.md` 第 3 节。

### 7.3 迁移题怎么写

迁移题的判据：**换掉情境，但考同一个结构**。

```
原题：3 个词的注意力权重，每行和为 1
迁移题：5 个词，其中两个是同义词，每行还和为 1 吗？（是，但分布会变）
```

只改数字不改情境（3 个词 → 4 个词）**不算迁移**，那只测了算术。

## 8. Step 7 细则：自评迭代（3.5% → 69.3% 的关键）

### 8.1 为什么必须多轮

Google Research 实测：**单次生成满足全部教学要求的概率只有 3.5%**；每轮只按某类 critique 找缺陷并修，10 轮后升到 69.3%。

注意是「10 轮迭代」不是「把提示词写长」。**这是迭代，不是提示工程。**

而且论文特别指出：**改善不是单调的**——修好视觉可能弄坏机械，所以要分轴反复过。

### 8.2 四类 critique（每轮只挑一类专查）

| 类别 | 逐条问 |
|---|---|
| **Visual** | 手机上挤不挤？长数字会不会撑破格子？深色背景对比度够吗？动画是不是在抢注意力？有没有文字截断？ |
| **Solution** | 演示里的数算对了吗？滑块拖到头会不会崩？目标真的能达成吗？边界值（0、负数、极大）怎么表现？ |
| **Telemetry** | 用户能看见自己操作的结果吗？中间量（不是只有最终答案）暴露了吗？错了以后知道错在哪一步吗？ |
| **Mechanical** | 有没有外部请求？控制台报错吗？按钮点了有反应吗？重开能回初始状态吗？滚动卡不卡？ |

### 8.3 迭代记录格式

写进交付说明，让别人（和未来的你）看得到：

```markdown
## 自评迭代记录

| 轮 | 类别 | 发现 | 修法 | 状态 |
|---|---|---|---|---|
| 1 | Solution | d=1024 时权重和是 100.0001% | 分数先减最大值再 exp | 已修 |
| 2 | Visual | 移动端 8 列表格横向溢出 | 加横向滚动 + 缩字号 | 已修 |
| 3 | Mechanical | 点「重置」后题目状态没清 | 重置时清所有 state | 已修 |
| 4 | Visual | 热力图配色在深色下看不清 | 未修 | **未修（已知限制）** |
```

**「未修」也要写。** 这正是 C7 要求的诚实喵。

### 8.4 什么时候停

- 连续一轮四类都找不出新问题 → 停
- 或者已修 10 轮 → 停，剩下的记成已知限制

不要为了凑轮数编问题。

## 9. 能力降级表

同 SKILL.md 第 6 节，这里给执行细节：

| 缺什么 | 具体怎么做 | README 里写什么 |
|---|---|---|
| 联网检索 | 用参数化知识，**不写具体论文编号/年份**（容易记错） | 「本课依据通用知识，未联网核验具体文献」 |
| 浏览器测试 | 跑 `validate-lesson.mjs`，再用 Node 假 DOM 抽页面 JS 跑数值断言 | 「数值逻辑已脚本验证；页面排版未实测」 |
| 代码执行 | 给可复制代码块 + 明确预期输出 | 「代码未实际运行，预期输出为推演结果」 |
| 专属预览 | 交付普通 HTML，附打开方式 | 「双击或 `python -m http.server` 打开」 |
| 持久化记忆 | 靠文件 + 用户反馈 | 「不记得上次课程内容」 |

**降级不是失败，谎报才是。** 用户看到「未实测」会自己检查；看到「已验证」而实际没验证，会踩坑。

## 10. 交付物结构

```
<课程目录>/
├── <主题>.html          # 课程本体，单文件零依赖
└── README.md            # 下面这份
```

README 模板：

```markdown
# <主题> 交互课程

## 学习目标
- <可验证的目标 1>
- <可验证的目标 2>

## 打开方式
双击 `<文件名>.html`，或 `python -m http.server` 后访问。
无需联网，无外部依赖。

## 课程结构
| 站 | 主题 | 交互 |
|---|---|---|

## 已检查
- [x] 数值逻辑：脚本断言 N 项全部通过
- [x] 零外部请求：grep 无 http:// 或 https://
- [x] 答后展开：答题前不显示答案

## 未检查 / 已知限制
- [ ] 页面排版：未在真实浏览器实测
- [ ] 移动端：未测
- 简化假设：演示用 d=4，真实模型 d=3584

## 自评迭代记录
见上表。

## 如何继续
卡在某一句 → 把原句贴给 Agent，要求「按卡点清单格式拆解」。
```
