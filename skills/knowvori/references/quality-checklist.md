# 质量检查清单

> 五维验收标准来自 Kovshov et al., arXiv:2609.20738 的教师评分 rubric（Google Research）。
> 用法：**先跑脚本，再过人工清单。脚本查得出来的不靠眼睛，眼睛查得出来的不靠脚本。**

---

## 0. 交付前的三道关

```
第一道：node scripts/validate-lesson.mjs <课程.html>    ← 机器能判的
第二道：本文档 1~5 节逐条过                            ← 只有人能判的
第三道：真实交互验收（第 7 节）                        ← 只有实际跑过才算
```

**通过第一道不等于合格。** 脚本只能查「有没有外部请求」「答案是不是答后展开」这类结构问题，查不出「讲解有没有制造理解错觉」，更查不出「交互是不是真的有效」。

**静态代码检查通过，不代表交互已经通过测试。**

---

## 1. Factuality（事实性）

| 等级 | 判据 |
|---|---|
| 0 失败 | 含事实错误，或与主流共识矛盾 |
| 1 通过 | 大体准确，有小瑕疵但不影响核心概念 |
| 2 良好 | 事实上准确，与当前共识一致 |
| 3 优秀 | 高度准确、可核验、有效表达共识 |

逐条查：

- [ ] 每个数值断言都算过或跑过（不是「应该差不多」）
- [ ] 简化假设**明确标注**了（「演示用 d=4，真实 3584」）
- [ ] 没联网时不写具体论文编号/年份（记错比不写更糟）
- [ ] 类比与事实分开标注（「这是个类比，实际机制是…」）
- [ ] 没有「据说」「一般认为」这种无法追溯的说法
- [ ] 代码跑过就写跑过，没跑就写「未运行」

**最常踩的坑**：为了讲得顺，把「大致如此」写成「就是这样」。**宁可多一句「这里简化了」。**

---

## 2. Alignment（与目标对齐）

| 等级 | 判据 |
|---|---|
| 0 失败 | 内容与声明目标不符 |
| 1 通过 | 松散对齐，部分内容与目标无关 |
| 2 良好 | 至少与一个明确目标对齐，进阶关系清楚 |
| 3 优秀 | 完全对齐，无冗余无遗漏 |

逐条查：

- [ ] 每个目标都有对应的演示或题目（`teaching-workflow.md` 第 2.2 节）
- [ ] 每个演示都能说出「它教哪个目标」
- [ ] 删掉任何一个演示，这节课会少学到东西（否则它是冗余）
- [ ] 没有「为了填版面」的知识点
- [ ] 难度递进是单调的，没有难度跳跃

**自检方法**：把课程标题遮住，只看内容，能让一个陌生人猜出学习目标吗？猜不出 → 散了。

---

## 3. SMART（目标本身的质量）

| 维度 | 判据 | 反例 |
|---|---|---|
| **S**pecific | 具体，不是泛指 | ❌「了解深度学习」 |
| **M**easurable | 可测量，动词可观察 | ❌「体会注意力的妙处」 |
| **A**chievable | 在给定时间内可达 | ❌ 20 分钟「掌握 Transformer」 |
| **R**elevant | 与用户实际需求相关 | ❌ 学面试却只在讲历史 |
| **T**ime-bound | 时间预算合理 | 超预算 2 倍 = 没砍干净 |

逐条查：

- [ ] 目标用的是可观察动词（算出/判断/补全/找出/预测）
- [ ] 目标数量 ≤ 3
- [ ] 字数在预算内（见 SKILL.md 第 4.3 节）
- [ ] 时间估算诚实：读完 + 动手 + 自测 ≈ 声明时长 × 1.5

**注意**：20 分钟课的实际耗时通常是声明的 1.5~2 倍。**声明时就按 1.5 倍算**，别等用户抱怨。

---

## 4. Clarity（清晰度）

| 等级 | 判据 |
|---|---|
| 0 失败 | 术语堆砌，难懂 |
| 1 通过 | 冗长或有冗余 |
| 2 良好 | 基本清楚，个别术语未拆 |
| 3 优秀 | 短、简、每个术语首次出现即拆 |

逐条查：

- [ ] **每个术语首次出现都拆了**（`teaching-workflow.md` 第 6.4 节）
- [ ] 每个结论前都有推导四句
- [ ] 至少有一个「不这样会怎样」的反例
- [ ] 句子平均长度 < 40 字（中文）
- [ ] 没有嵌套三层以上的从句
- [ ] 数字带单位（「3584 个数字」而不是「3584」）
- [ ] 缩写首次出现给全称

**零基础档特别查**：连「形状」「参数」「向量」「维度」这类词都拆了吗？

---

## 5. Progression（递进性）

| 等级 | 判据 |
|---|---|
| 0 失败 | 难度跳跃，无逻辑顺序 |
| 1 通过 | 有递进但不够平滑 |
| 2 良好 | 依次递增难度与认知层次 |
| 3 优秀 | 完美脚手架，单调递增 |

逐条查：

- [ ] 每一站的卡点，前置都在前面讲过
- [ ] 没有「用后面才讲的概念解释前面」（这是最常见的倒序错误）
- [ ] 认知层次递进：认得出 → 能算 → 能判断 → 能迁移
- [ ] 每站结尾有一句「下一站要解决什么」的钩子
- [ ] 卡点数 5~7（多了砍，少了展开）

**检验方法**：从最后一站往前读。每句话里出现的概念，在前面都能找到定义吗？找不到 → 顺序错了。

---

## 6. 交互设计检查（设计层）

| 类别 | 逐条查 |
|---|---|
| **对象化** | 抽象概念在页面上有可观察载体吗？删掉载体后讲解会塌吗？ |
| **动态过程** | 中间状态和中间量暴露了吗？用户能看到「第 2 步到第 3 步」怎么变吗？ |
| **主动操作** | 用户能改真实变量吗？能暂停、继续、重复、重置吗？ |
| **反馈闭环（C8）** | 操作 → 状态变化 → 结果反馈 → 原理解释，四环都在吗？ |
| **Solution** | 演示的数算对了吗？乱填会崩吗？边界值（0/负/极大/空）正常吗？目标真的能达成吗？ |
| **Telemetry** | 用户能看到操作结果吗？中间量暴露了吗？错了知道错哪一步吗？ |
| **Mechanical** | 零外部请求？控制台报错？按钮都有响应？重置能回初始？滚动卡吗？ |
| **Visual** | 手机不溢出？深色 / 浅色都可读？动画不抢戏？无文字截断？触控目标 ≥40px？ |

---

## 7. 真实交互验收（必须实跑）

这一节不能靠读代码完成。**要在真实浏览器里动手点、拖、输入、暂停、重置，再断网打开一次。**

| 验收项 | 怎么验 | 不通过的典型表现 |
|---|---|---|
| **交互真正有效** | 实际走一遍「操作 → 状态变化 → 结果反馈 → 原理解释」 | 点了有反应，但学习目标没被推进；或只能看不能操作 |
| **数据与动画同步** | 改参数，手算一次，和页面显示对一遍 | 动画演示的和实际计算的不是同一回事 |
| **可重复 / 暂停 / 重置** | 连续操作 3 次；暂停再继续；重置后回初始态 | 第二次操作状态残留；暂停只是停帧；重置清不干净 |
| **极端输入** | 输入 0、负数、空、超大值、超长文本、非法字符 | 除零、NaN、溢出、卡死、报错后无法恢复 |
| **手机屏幕** | 375px 宽度或真机；触控操作一遍 | 横向溢出、按钮太小、滑块够不着、关键内容靠 hover |
| **断网环境** | 断开网络后双击打开；或 `file://` 直接打开 | 字体/图表/图标加载失败，交互整块不可用 |

逐条记录结果。**没跑过的项，在 README 写「未实测」，不要写成「已验证」。**

## 8. 自评迭代记录（必须写进 README）

| 轮 | 类别 | 发现 | 修法 | 状态 |
|---|---|---|---|---|
| 1 | 教学检查 | | | 已修 |
| 2 | 交互检查 | | | 已修 |
| 3 | 体验检查 | | | 未修（已知限制） |

**三类检查各至少 1 轮。** 依据：单次生成合格率 3.5%，反复按维度 critique 后可显著提升（arXiv:2609.20738）。但**不要把「10 轮」当成每次的硬指标**——论文里的 10 轮是实验设置，不是课程合格线。

每轮必须落到具体维度：发现问题写修法；没发现问题，就写「已确认：XX 维度无新问题」。不重复空转，也不为了凑轮数编问题。

---

## 9. 技能等级（这五维能拿几分）

| 总分 | 判定 |
|---|---|
| 任何一维 0 | **不合格**，必须重做 |
| 平均 1 | 勉强可用，用户会觉得「像 AI 生成的」 |
| 平均 2 | 能用，但没惊喜 |
| 平均 3 | 优秀 |

**注意：任何一维判 0 就整体不合格**，不能靠其他维度的高分拉平。一个事实错误就能毁掉整节课。

## 10. 最终交付清单

```markdown
## 已检查
- [x] 数值逻辑：脚本 N 项断言全部通过
- [x] 零外部请求：无 http:// / https:// / CDN 引用
- [x] 答后展开：答题前不显示答案
- [x] 迁移题：至少 1 道
- [x] 干扰项：每题 ≥2 个来自真实误解
- [x] 自评迭代：教学 / 交互 / 体验三类各至少 1 轮，记录在案
- [x] 交互闭环：每个交互都能走完「操作 → 状态 → 反馈 → 解释」
- [x] 交互实测：重复、暂停、重置、极端输入均已试过（或在下方标「未实测」）

## 未检查 / 已知限制
- [ ] 页面排版：未在真实浏览器实测（或：已在 Chrome 1440px 实测）
- [ ] 移动端：未测（或：已在 375px 宽度实测）
- [ ] 断网双击：未测
- [ ] 深色 / 浅色主题：未测
- [ ] 代码未实际运行
- 简化假设：演示用 d=4，真实模型 d=3584

## 自评迭代记录
| 轮 | 类别 | 发现 | 修法 | 状态 |
|---|---|---|---|---|

## 如何继续
卡在某一句 → 贴原句给 Agent，要求「按卡点清单格式拆解」
想要第 2 节 → 说「继续做 <主题> 第二节」
```

**「未检查」这一栏空着 = 谎报。** 一定有你没查的东西，写出来。

## 11. 快速自查（30 秒版）

来不及全查时，查这 7 条（按破坏力排序）：

1. **有没有事实错误？**（一个就够毁掉全部）
2. **每个结论前有推导吗？**（没有 = 制造理解错觉）
3. **术语都拆了吗？**（没拆 = 断台阶）
4. **答完才展开吗？**（提前展开 = 学习效果归零）
5. **演示是真算的吗？**（假数字 = 一改就露馅）
6. **交互能走完闭环吗？**（只能播动画 = 只是观看）
7. **有迁移题吗？**（没有 = 只测了记忆）

这 7 条过不了，其他细节不用看了喵。
