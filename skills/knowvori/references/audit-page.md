# audit-page.mjs · 浏览器审计

`validate-lesson.mjs` 读的是源码字符串，它能确认「有没有绑定事件」，但不能确认「点了到底有没有反应」「390px 下会不会横向溢出」。这些只能真打开页面才知道。

这个脚本补齐那一段。

```bash
node skills/knowvori/scripts/audit-page.mjs skills/knowvori/examples/*.html
```

## 六项检查

| 检查 | 抓什么 | 为什么静态检查做不到 |
| --- | --- | --- |
| 运行时报错 | 加载和交互过程中有没有 `console.error` / 未捕获异常 | 需要真的执行脚本 |
| 零外部请求 | 实际发出的网络请求里有没有非 `file://` 的 | 字符串里没写不代表运行时不偷偷发 |
| 横向溢出 | 320 / 390 / 768 / 1100px 下有没有横向滚动，并指出是哪个元素越界 | 要真的排版一次才知道 |
| 文字裁切 | 有没有文字被容器裁掉一半 | 依赖实际字体和换行 |
| 深色对比度 | 深色模式下正文、按钮的对比度是否达标（WCAG AA） | 要解析实际计算后的颜色，包括继承和背景叠加 |
| 练习可作答 | 每组自测题点一下，确认真的出现反馈 | 要真的点 |

## 它抓到过什么

写这个脚本的直接原因，是想让 README 里「320/390/768/1100px 无横向溢出」「16 道题逐题点过」这些说法能被复现，而不是只有我一个人在某个下午手动点过。

第一次跑就抓到一个真 bug：`binary-search-detective.html` 的主按钮在深色模式下是浅粉底配近白字，对比度 1.88:1，远低于 AA 要求的 4.5:1。

原因是 `.btn.primary { background: var(--pink); color: var(--ink) }`，而深色模式把 `--pink` 调成了浅粉（`#ff8fb3`）、`--ink` 调成了近白（`#f9edf3`）。浅色模式里这两个值一深一浅，看着正常；换成深色就撞在一起了。

修法是给填充按钮固定深色文字，而不是跟着 `--ink` 走 —— 浅底配深字本来就是「填充按钮」该有的读法。

这类 bug 静态检查永远抓不到：源码里两个变量名都完全合理。

## 选项

| 选项 | 说明 |
| --- | --- |
| `--widths=320,390,768,1100` | 要测的视口宽度 |
| `--json=out.json` | 结果写成 JSON，便于 CI 或对比 |
| `--no-quiz` | 跳过练习点击，只测布局 |

退出码：`0` 无 error，`1` 有 error，`2` 用法错误。

## 依赖

需要 `playwright-core` 和一个 Chromium 或 Edge。脚本按 `msedge` → `chrome` → 自带 Chromium 的顺序找，找到一个就用。

```bash
cd tools/audit-deps && npm install     # 已有的话直接复用
```

脚本会在自己所在目录、仓根、`tools/audit-deps`、`NODE_PATH` 里依次找 `playwright-core`，所以通常不用额外配。

## 边界

- **无 error ≠ 课程合格**。这六项只覆盖「能不能用」，不覆盖「讲得对不对」。教学判断仍要走 `references/quality-checklist.md`。
- 深色对比度只检查纯文本节点，渐变背景上的文字算不准，会漏。
- 没有跑真机触控、Safari / Firefox、屏幕阅读器完整流程。3D 场景在 headless 下走软件 WebGL，低端 GPU 表现未覆盖。
- 练习点击只验「有反馈」，不验「反馈内容对不对」。内容对不对得靠人看。
