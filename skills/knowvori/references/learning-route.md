# 学习路线（多天课程体系）

> 单节课只能解决一个卡点。**目标是「21 天学会 X」时，需要的是路线，不只是课。**

这份文档定义路线层的做法：怎么把一个大目标拆成若干天、怎么保证天与天接得上、汇总页要有什么、以及怎么让进度真的存下来。

---

## 1. 什么时候做路线，什么时候只做单课

**先问一句：用户的目标有没有时间跨度？**

| 用户说 | 做 | 不做什么 |
|---|---|---|
| 「我想理解 Attention」 | 单课 | 不要拆成 5 天，那是灌水 |
| 「21 天学会机器学习」 | **路线**（汇总页 + N 节课程） | 不要在一节课里塞 21 天的内容 |
| 「准备三个月后的算法面试」 | 路线，但先只做前 3 天 | 不要先排满 60 天再动手——第 4 天必然要改 |
| 「帮我制定学习计划」 | **先做路线骨架 + 第 1 天完整课** | 不要只交一张计划表——那是大纲，不是课（见 SKILL.md §7） |

### 1.1 一条铁律

**路线里每一天，本身必须是一节合格的课。**

拆成 21 天不等于把 21 个小标题各配一段话。每天都要满足单课的全部要求：可验证目标、卡点、真实交互、推导四句、自测、动手。做不到这点的「天」，应该合并进相邻的一天。

判据：**抽掉任意一天，前后两天接不上，才算拆对了。** 如果某天可以随意删掉而没人察觉，那天就是凑数的。

### 1.2 天数从哪来

不要先定「21 天」再往里填内容。**先数卡点，再定天数。**

```
天数 ≈ 卡点数 ÷ 每天能攻克的卡点数
```

每天能攻克的卡点数，取决于先验档位：

| 先验档位 | 每天卡点数 | 每天时长 | 说明 |
|---|---|---|---|
| 零基础 | 1 | 30~45 分钟 | 一个卡点 + 一个练习，再多就吸收不了 |
| 有编程基础 | 1~2 | 45~60 分钟 | 可有 1 个复习型卡点 |
| 有领域基础 | 2~3 | 30~45 分钟 | 直接上难点 |

**如果用户指定了天数**（「就要 21 天」），先验证可行性：
- 算出来的天数 ≈ 21（±20%）→ 按 21 天排
- 算出来只有 9 天 → **说出来**：「这个目标按你的基础大约 9 天能到，硬拆 21 天会有 12 天在灌水。要 21 天的话，建议把目标扩到 X（比如加上实战项目），或者每天 20 分钟慢慢来。」
- 算出来要 40 天 → 同理，建议砍目标或提高每天投入

**不要为了凑天数注水。** 21 天里有 12 天是废话，用户会在第 3 天放弃。

## 2. 路线蓝图（写 HTML 前必须先写）

和单课蓝图一样，**文本，不是网页**。

```markdown
## 路线蓝图

**路线**：21 天入门机器学习
**终点能力**（一句话，可验证）：给定一份陌生 CSV，能独立完成「清洗 → 训练 → 评估 → 解释结果」全流程，并说出模型为什么可能过拟合
**起点**：会 Python，不会线代，没碰过 sklearn
**总投入**：21 天 × 45 分钟

### 阶段划分（每一阶段有独立可交付成果）
| 阶段 | 天数 | 主题 | 阶段末能做什么 |
|---|---|---|---|
| A · 数据直觉 | Day 1–6 | 数据、分布、相关性 | 看一眼数据能说出「哪列有问题」 |
| B · 模型原理 | Day 7–13 | 线性回归 → 逻辑回归 → 过拟合 | 手推一次梯度下降，能解释正则项 |
| C · 工程实践 | Day 14–18 | sklearn 流程、特征工程、交叉验证 | 跑通完整 pipeline，能调参不瞎试 |
| D · 综合项目 | Day 19–21 | 端到端项目 | 独立完成一个项目并写清结论 |

### 每天的卡点与产出
| Day | 卡点 | 学完能做什么 | 依赖 | 交互形态 |
|---|---|---|---|---|
| 1 | 「数据长什么样」说不清 | 能对一列数据说出分布形状与异常 | — | 直方图调参 |
| 2 | 分不清均值和中位数什么时候用 | 能选对统计量并说明理由 | Day 1 | 拖异常值看点变化 |
| 3 | ... | ... | Day 2 | ... |
```

### 2.1 依赖关系必须显式写

每天一行「依赖」列。**这张表是后面所有检查的依据**：

- 如果 Day 7 依赖 Day 5 的「梯度」概念，那 Day 5 必须真的讲到，且 Day 7 开头要回指。
- 依赖成环 → 拆错了，重排。
- 某天没有任何后续依赖 → 要么是终点，要么是废课。

### 2.2 阶段必须有自己的交付物

「阶段末能做什么」必须是**可观察的产物**，不是「理解了」：

- ✅ 「能对一列数据说出分布形状与异常」
- ✅ 「跑通完整 pipeline，F1 > 0.7」
- ❌ 「掌握数据预处理」

阶段交付物的作用：**用户在第 6 天结束时能感到「我完成了一块」**。21 天连着走没有里程碑，第 8 天就会怀疑自己在干什么。

## 3. 汇总页（route.html）规格

汇总页是路线的入口。它**不是目录**，是**驾驶舱**。

### 3.1 必须有的六块

| 区块 | 内容 | 为什么必须 |
|---|---|---|
| **① 终点** | 一句话：21 天后你能做什么（可验证） | 让人知道自己在往哪走 |
| **② 进度** | 「已完成 7 / 21 天 · 阶段 A 完成」+ 进度条 | 知道自己在哪 |
| **③ 今天该学** | 高亮下一个未完成的天，一个大按钮 | **降低每次启动的成本**——这是留存的关键 |
| **④ 路线图** | 按阶段分组的天卡片，显示状态（未开始/进行中/已完成） | 看到全貌与已走过的路 |
| **⑤ 依赖提示** | 若某天的前置未完成，卡片上标注「建议先完成 Day 5」 | 防止跳到一半学不懂而放弃 |
| **⑥ 说明边界** | 总投入、前置要求、哪些天可跳过 | 诚实（C7） |

### 3.2 不要有的

- ❌ **不要做成纯目录**（一串链接 = 大纲，SKILL.md §7 已禁止）
- ❌ **不要用分数 / 打卡连续天数 / 排行榜**（SKILL.md §7 禁止用刷分做激励）
- ❌ 不要强制顺序锁死。标注依赖，但**不拦人**——用户想先看 Day 12 就让他看，只是提示前置未完成

### 3.3 「今天该学」的判定逻辑

这是汇总页最核心的一小块代码，也是最容易被写成死数据的：

```js
// 从 localStorage 读进度，找出第一个未完成的天
// 注意：不是「最后访问的天 + 1」，是「第一个未完成的天」
// ——用户可能跳着学完了 Day 5，Day 3 还没做
function nextDay(days, progress) {
  for (const d of days) {
    if (!progress[d.id]) return d;      // 第一个没完成的
  }
  return null;                           // 全部完成
}
```

**边界情况必须处理：**
- 全部完成 → 显示「路线走完了」+ 建议（复习、或下一个路线）
- 一天都没开始 → 指向 Day 1
- 进度数据损坏 / 是老版本格式 → 当作全部未完成，不要崩

### 3.4 汇总页也要能自动演示

沿用 `assets/replay-engine.js`：点「▶ 看一遍演示」，模拟「点开 Day 1 → 完成 → 回到汇总页 → 进度条前进 → 今天该学变成 Day 2」。

这一条演示**直接回答用户最大的疑问**：「这玩意儿怎么用」。比任何文字说明都有效。

## 4. 进度存储：route-progress.js

### 4.1 为什么单独一个文件

- **单文件交付原则不破**：每节课仍然自己一个 HTML，断网双击能开。
- 进度**不属于任何一节课**，属于这条路线。存进某节课里，换节课就丢了。
- `file://` 下 localStorage 可用，且**同目录的不同 HTML 共享**（已实测）。所以汇总页和每天课程能读写同一份进度。

### 4.2 数据格式

```js
// key: 'kv:route:<routeId>'
{
  "v": 1,                              // 版本号，格式变了要能识别旧数据
  "route": "ml-21",                    // 路线 id
  "done": { "day-1": 1699999999999 },  // 完成时间戳，没有就是未完成
  "visited": { "day-1": 1699999999999 },
  "notes": { "day-2": "卡在正则项" }    // 可选：用户自己记的一句
}
```

**为什么存时间戳而不是布尔值**：可以回答「哪天学的」「隔了多久」，也方便排查进度丢失。布尔值省不了多少空间。

### 4.3 「完成」怎么判定

**不能用「打开过就算完成」**——那是自欺。

完成条件（每节课自己判断，写在课程末尾）：

| 条件 | 说明 |
|---|---|
| 自测题全部作答 | 不要求全对（答错也是学习），但必须都答过 |
| 动手题提交过 | 至少点过一次「检查」/「运行」/「看答案」 |
| 显式确认 | 最后有「我今天学完了」按钮，用户自己点 |

三条都满足才算 `done`。**课程里要写清楚判定标准**，不能偷偷算。

### 4.4 降级：存不了怎么办

`localStorage` 可能被禁用（隐私模式、某些浏览器策略）。**必须优雅降级**：

- 读写全用 try/catch 包住
- 存不了 → 页面顶部显示一行低调提示「本次进度不会被记住（浏览器限制）」，**不弹窗、不阻断学习**
- 汇总页仍能显示路线，只是状态全是未开始
- 不要因为存不了就报错或白屏

## 5. 天与天之间怎么接（最容易翻车的地方）

第 8 天写得很好，但用户在第 7 天没学会第 7 天的东西 → **第 8 天一开始就卡死**，然后放弃。

### 5.1 每天开头必须有「回指」

```html
<!-- 每节课开头，紧接前置检查之后 -->
<div class="recap">
  <p>昨天你搞清了「为什么要除以 √d」——因为维度越大点积越容易爆。</p>
  <p>今天要用到这一点：如果没印象，<a href="day-07.html">先回去看一眼 Day 7</a>，五分钟就够。</p>
</div>
```

三条要求：
1. **说清昨天具体学了什么**（不是「昨天学了注意力」这种废话）
2. **说清今天哪里会用到它**
3. **给回去的链接**

### 5.2 每天结尾必须有「明天预告 + 今天没讲什么」

```html
<div class="next-up">
  <p><strong>明天（Day 9）</strong>：我们会用今天学的正则项，解释为什么你的模型在测试集上崩了。</p>
  <p>今天没讲的：L1 和 L2 的区别、以及为什么 L1 会稀疏。Day 11 讲。</p>
</div>
```

**「今天没讲什么」比「明天讲什么」更重要**——它防止用户以为漏学了，去别处乱找。

### 5.3 断点续学

用户可能隔一周才回来。汇总页要回答：**我上次学到哪了？**

- 读 `visited` 里最近的时间戳 → 「上次学到 Day 7（3 天前）」
- 不评判、不催促（不做「你已经 7 天没学习了！」这种），只陈述

## 6. 交付物结构

```
<路线目录>/
├── route.html              # 汇总页 = 入口，含进度、今天该学、路线图
├── route-progress.js        # 进度读写（内联进每个 html，或作为本地文件）
├── day-01.html              # 第 1 天，完整的单课
├── day-02.html
├── ...
├── day-21.html
└── README.md                # 路线说明 + 已检查 / 未检查
```

**注意**：`day-XX.html` 是**各自独立的单文件课程**，不依赖 `route-progress.js` 也能看能学（进度只是增强）。这样用户把某一天的 HTML 单独发给别人，对方也能正常学。

所以进度脚本要**内联进每个 html**，而不是外链 `<script src>`。理由和 replay-engine 一样：单文件交付不能 import。

---

## 7. 生成顺序（重要）

**不要先写 21 个 HTML 再拼汇总页。**

```
1. 路线蓝图（文本）            ← 想不清就别动手
2. route.html（汇总页骨架）    ← 先用假数据把驾驶舱做出来
3. day-01.html（完整一课）     ← 打通一节，验证结构与进度接口
4. 让用户试 Day 1 + 汇总页     ← 拿到反馈再往下
5. day-02 ... day-0N            ← 按阶段推进，每阶段结束交付一次
6. 回填 route.html 真实数据     ← 天标题、卡点从写好的课里取
```

**为什么第 4 步不能省**：如果 Day 1 的时长、难度、风格不对，21 天全错。改一天的成本是改 21 天的 1/21。

**为什么不要一次做 21 天**：一条路线 21 课，每课按单课标准做完是很大工作量。先做 Day 1 验证，再按阶段（A/B/C/D）分批交付，用户每阶段末能拿到可用的东西。

## 8. 汇总页验收清单

除了单课的 validate/audit，汇总页额外要查：

- [ ] 有终点句、进度、今天该学、路线图、依赖提示、边界说明六块
- [ ] 「今天该学」是**算出来的**，不是写死的（改 localStorage 后刷新应变化）
- [ ] 全部完成 / 未开始 / 数据损坏 三种边界都不崩
- [ ] 点了某天的「完成」后，进度与「今天该学」真的更新
- [ ] localStorage 被禁用时，页面正常显示，只是进度不保存
- [ ] 每个 day-XX 链接都真实存在（没有 404 的空壳）
- [ ] 汇总页有「▶ 看一遍演示」且能跑完
- [ ] 手机宽度下卡片不溢出、触控目标 ≥ 40px
- [ ] 深色 / 浅色都清晰
- [ ] 没有打卡连续天数 / 分数 / 排行榜

## 9. 反面例子

| 做法 | 为什么错 |
|---|---|
| 21 天全是「阅读资料 + 做笔记」 | 不是交互课，是读书清单（违反 SKILL.md §7） |
| 汇总页只有一张 21 行表格 + 链接 | 是目录不是驾驶舱，用户不知道今天该干嘛 |
| 「今天该学」写死在 HTML 里 | 学完第 1 天还是让你学第 1 天 |
| 每天只有 300 字 + 2 道选择题 | 一天攻不下一个卡点，等于 21 天都在划水 |
| 用打卡连续 21 天奖励徽章 | 把学习变成刷分，SKILL.md §7 明确禁止 |
| 强制顺序，跳一天就锁住后面的 | 用户想跳着看就让他跳，只提示不拦 |
| 第 8 天假设用户记得第 7 天细节 | 没有回指，用户必然卡死 |

## 10. 照哪个做

- 汇总页模板：`assets/route-template.html`（占位符版，`tools/inline-engines.mjs` 填引擎）
- 进度引擎：`assets/route-progress.js`（`KVProgress ▸ v1`，带版本号 schema，存不了降级内存）
- 完整样例：`examples/route-5days/` —— 5 天示例路线，含真算演示、自动回放、跨文件进度，是本规范的可运行参考
- 生成方式：`node tools/build-route-demo.mjs`（示例用的是生成器；真实路线可手写，但结构务必与样例一致）

改完必须跑：

```bash
node skills/knowvori/scripts/validate-lesson.mjs skills/knowvori/examples/<route>/day-*.html
node skills/knowvori/scripts/validate-route.mjs  skills/knowvori/examples/<route>/route.html
node skills/knowvori/scripts/audit-route.mjs     skills/knowvori/examples/<route>/route.html
```

注意：`validate-lesson.mjs` 会识别汇总页并跳过、提示改用 `validate-route.mjs`。如果你把 `day-*.html` 和 `route.html` 一起传给日课校验器，那条 warning 是预期的，不是错误。
