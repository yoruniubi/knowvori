第 1 站

坑在哪：exp 会撞天花板

你通常看到的 softmax 写法是这三行：

e = x.map(Math.exp)      // 指数化
s = sum(e)               // 求和
p = e.map(v => v / s)    // 归一化

看起来天经地义。问题出在第一行——它有个硬上限喵。

「浮点数」不是无限精确的数，它有自己的最大值。双精度（float64）能表示的最大值大约 1.8×10³⁰⁸，超过就直接变成 Infinity。

就像车速表最大刻度 300——你开到 400 它不会显示 400，只会顶在 300 那或者直接罢工。数字到了天花板，就不再是它本身了。

现象你会看到：exp(709) 还算得出来，exp(710) 就是 Infinity。差 1，结果就不是数了。
为什么因为 exp(709) ≈ 8.2×10³⁰⁷，已经很接近 float64 的天花板；再乘 e 就溢出了。这是浮点格式的位数决定的，不是你写错代码。
所以于是就有了那条看起来莫名其妙的「先减去最大值」——不是为了算得快，是为了永远别让 exp 靠近天花板。
不这样假如不减，e 里全是 Infinity，s 也是 Infinity，最后 Infinity / Infinity = NaN。结果不是「精度差一点」，是整组概率全部报废。

第 2 站

救法：减 max 为什么不算作弊

稳定版只在指数化前多做一件事：整组分数一起减掉最大值。

m = Math.max(...x)
e = x.map(v => Math.exp(v - m))   // 减完，最大值那项 exp(0) = 1
s = sum(e)
p = e.map(v => v / s)
现象减完之后，e 里最大的一项恰好是 1，其余都 ≤ 1。永远不可能溢出。
为什么因为 softmax 上下同除一个正数结果不变：exp(xᵢ-m) / Σexp(xⱼ-m) 分子分母都约掉了 exp(-m)，等于原来的 exp(xᵢ) / Σexp(xⱼ)。数学上同一个东西。
所以于是「减 max」是纯白拿的：数学结果不变，数值安全性全得。没有任何代价，所以所有正经实现都这么写。
不这样假如你以为「减了就会改变概率分布」而不改，那模型一训练就出 NaN，你还得花半天怀疑是学习率的问题——而真正的原因在归一化那三行里。

「上溢 / 下溢」：数太大超出上限叫上溢（变 Infinity），太小贴近 0 被舍掉叫下溢（变成 0）。极端负数分数会走下溢那条路。

减 max 同时治两头：最大项变 1（防上溢），最小项相对差距被拉近（减轻下溢）。

找出下面这段代码里的一处问题

① e = x.map(v => Math.exp(v - x[0])) 减的是第一个元素，不是最大值——想想 x 全为负数时会怎样
② s = e.reduce((a,b) => a+b, 0) 这一步其实是对的——也要允许你判定「这里没问题」
③ p = e.map(v => v / s) 这一步也是对的

这几题是客观校验（答案唯一、可机判）。至于「你能不能自己写对」，那需要你动手跑一遍，本页不给评分喵。

Q1为什么 exp(710) 会失败，而 exp(709) 不会？

要点

exp 对任何实数都有定义，它本身不会「拒绝」某个输入。失效的是结果的存储：exp(709)≈8.2e307 还在 float64 上限（约 1.8e308）之内，exp(710) 就越界了。所以边界落在 709 与 710 之间，而不是某个「函数规则」上。

Q2先减掉最大值再 softmax，输出的概率分布会变吗？

要点

把分子分母写成展开式：exp(xᵢ-m) / Σexp(xⱼ-m)，分子分母同时含因子 exp(-m)，约掉后就是原来的 exp(xᵢ) / Σexp(xⱼ)。因为 exp 恒为正，这个约分对任意实数 m 都成立，与正负无关。

Q3稳定版里，指数化之后最大的一项等于多少？

要点

最大项减自己得 0，exp(0)=1；其余项指数为负，落在 (0,1) 之间。所以指数化后 e 的最大元素恒为 1，求和范围是 (1, n]——这就是它永远溢不出去的原因。注意别和「归一化后最大概率」混：那是另一个数。

Q9 · 迁移题你要把向量 x = [1e200, 1e200] 归一化成单位长度，写成 v / Math.sqrt(v·v)。会出什么事？

要点

危险的结构是「先放大再求和」，与有没有 exp 无关。1e200² = 1e400 溢出成 Infinity，sqrt(Infinity)=Infinity，每个分量变成 1e200/Infinity = 0。修法和 softmax 同一招：先按最大绝对值缩放再算，比值不变。

动手

自己跑一遍，亲眼看到 NaN

复制到浏览器控制台或 node 里跑。这段代码会同时打印朴素版和稳定版：

const naive = v => {
  const e = v.map(Math.exp);
  const s = e.reduce((a, b) => a + b, 0);
  return e.map(x => x / s);
};
const stable = v => {
  const m = Math.max(...v);
  const e = v.map(x => Math.exp(x - m));
  const s = e.reduce((a, b) => a + b, 0);
  return e.map(x => x / s);
};
console.log(naive([0, 1, 2]));
console.log(stable([0, 1, 2]));
console.log(naive([710, 711, 712]));
console.log(stable([710, 711, 712]));
