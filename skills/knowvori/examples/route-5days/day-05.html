第 1 站 · 卡点

在训练集上完美，不等于学到了规律

你把模型调到训练误差几乎为 0，结果换一批数据，预测一塌糊涂。训练已经「完美」了，问题出在哪？

「过拟合」模型把训练数据里的噪声也当规律记住了，所以在新数据上表现差。

就像背题：把练习册答案全背下来，考试换个数字就不会了。

「正则化」在损失里加一项「参数别太大」的惩罚，逼模型用更简单的解释。

就像规定「不许把答案写得过于复杂」，逼你用简单规则。

现象模型复杂度提高时，训练误差单调下降，但测试误差先降后升，呈 U 形。
为什么复杂度低时欠拟合，两边都差；刚合适时学到了真实规律；再往上开始拟合噪声，训练误差还能更低，但那些「规律」在新数据上不成立。
所以于是判断好坏不能只看训练误差，必须留出没参与训练的测试集。训练误差和测试误差的差距，就是过拟合的度量。
不这样假如只用训练误差挑模型，永远会选最复杂的那个 —— 它在训练集上一定最好看，而这恰恰最可能过拟合。

第 2 站 · 自测

先答，答完才看解释

反馈类型：客观校验（每题有唯一正确答案，选完立刻判定）。 第 3 题是迁移题 —— 换一个没在这节课出现过的新情境。

1. 训练误差 0.01，测试误差 0.45。最可能是？

训练和测试差距巨大（0.01 对 0.45），说明模型记住的是训练集的细节而不是规律。
欠拟合是两边都高，比如训练 0.5、测试 0.5。
0.01 对 0.45 的差距过大，不正常。
差距本身就是信号，足以判断。

2. 为什么增加复杂度时，测试误差会先降后升？

一开始模型太简单学不到规律（欠拟合）；复杂度合适时刚好学会；再复杂就记噪声，而噪声在新数据上不成立，于是测试误差回升。
恰恰不是，它呈 U 形。
即使测试集很大，U 形依然存在。
这是系统性的规律。

3. 迁移：10 万条数据、100 万参数，相比 1000 条数据、同样模型，过拟合风险如何？

过拟合风险取决于数据量和模型容量的比例。数据远多于参数时，记住噪声的代价很高（会明显损害训练集上的整体拟合），所以不容易发生。这也是大数据能撑起大模型的原因之一。
数据量是关键变量。
更多数据通常降低过拟合风险。
这个比例足以判断趋势。
第 3 站 · 动手

扫一遍复杂度，找出测试误差最低的点

const train = (c) => 0.9 * Math.exp(-0.55 * c);
const test  = (c) => 0.05 + 0.35 * Math.exp(-0.55 * c) + 0.045 * c * c;

let best = { c: 0, e: Infinity };
for (let c = 1; c <= 12; c++) {
  if (test(c) < best.e) best = { c, e: test(c) };
  console.log(`复杂度 ${c}: train=${train(c).toFixed(3)} test=${test(c).toFixed(3)}`);
}
console.log('最佳复杂度:', best.c);
预期输出
复杂度 1: train=0.519 test=0.248 复杂度 2: train=0.300 test=0.161 复杂度 3: train=0.173 test=0.133 复杂度 4: train=0.100 test=0.155 ... 复杂度 12: train=0.001 test=6.565 最佳复杂度: 3
已运行。复杂度 3 时测试误差最低（0.133）。往后训练误差还在降（12 时只剩 0.001），但测试误差爆到 6.5 —— 只看训练误差会选到 12。
