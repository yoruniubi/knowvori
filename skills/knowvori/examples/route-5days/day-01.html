第 1 站 · 卡点

误差不是感觉，是一个能算出来的数

你听说「这条线拟合得不错」——但不错是指什么？凭眼睛看？那换个人看结论就变了。

「残差」「这条线在这个点上的预测值」减去「真实值」，一个点一个数，有正有负。

就像考试的估分：你估 80，实际 72，残差就是 +8。

「平方误差和」把每个残差平方后加起来。平方是为了让正负不互相抵消，也顺便重罚大错。

就像算总偏差时不说「+8 和 −8 加起来是 0」，而是各算 8²，一共 128。

现象这堆点上能画无数条线，每条的「错得有多离谱」都不一样。
为什么一条线的误差 = 每个点的残差平方之和。残差越大，平方后放大得越快，所以偶尔的离谱点会主导总分。
所以于是「拟合得好」有了明确含义：让这个平方误差和尽量小的那条线。感觉就变成了一个可优化的目标。
不这样假如只看「残差之和」，正负会互相抵消 —— 一条穿过点堆正中的瞎画线，残差和可能是 0，但它显然不是最好的线。

第 2 站 · 自测

先答，答完才看解释

反馈类型：客观校验（每题有唯一正确答案，选完立刻判定）。 第 3 题是迁移题 —— 换一个没在这节课出现过的新情境。

1. 有两个模型。A 的残差是 [+3, −3, +3, −3]，B 的是 [+5, 0, 0, −1]。谁的平方误差和小？

B 是 25+0+0+1=26，A 是 9×4=36。A 的单点误差看着更「均匀」，但平方放大的是大错 —— B 因为多数点几乎没错，总分反而更低。
算一下：A 是 9+9+9+9=36，B 是 25+0+0+1=26。A 并没有更小。
两者都等于各自残差平方之和，但数字不同：36 对 26。
都是同一批点上的残差，可以直接比。

2. 为什么用残差的平方，而不是绝对值？

绝对值在 0 点不可导，优化时会卡住。平方处处可导，且增长快，等于更严厉地惩罚离谱点。
绝对值算得更快。选平方的主要理由是可导性和对大错的惩罚。
正相反，平方会放大异常值的影响。这也是它常被批评的地方。
有明确理由：可导 + 惩罚大误差。

3. 迁移：如果数据里有一个极端离群点（其余点都在 0~10，它却是 500），平方误差会怎样？

残差平方后，500 这个点的误差可能是其余所有点之和的几十倍。最小化总误差时，模型会牺牲其他点去迁就它。这也是为什么有离群点要先检查，或者换 Huber 之类的鲁棒损失。
平方放大的正是「一条离群点」，它的影响可能压倒其余全部数据。
会让其余点更不准。
恰恰相反，平方误差最不忽略它。
第 3 站 · 动手

亲手算一遍误差，确认你理解的是数不是感觉

// 三个点的真实 y，和一条线的预测 yhat
const y    = [3, 5, 4];
const yhat = [2, 4, 5];

// 残差、平方误差和（自己算完再看输出）
const resid = y.map((v, i) => v - yhat[i]);
const sse   = resid.reduce((s, r) => s + r * r, 0);

console.log(resid); // 应该是什么？
console.log(sse);   // 应该是什么？
预期输出
[ 1, 1, -1 ] 3
已运行。如果 sse 算成 1，说明忘了平方；算成 1+1−1=1，说明既忘了平方又没取绝对值。
