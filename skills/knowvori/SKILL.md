# knowvori · 交互式学习

## 0. 一句话定位

> **说出你想学什么，拿到一节能动手探索、通过练习检查理解的交互课程。**
> **说一个更大的目标（比如「21 天入门 XX」），拿到一条拆好天的路线 + 一张汇总页。**

三个词：**卡点 / 动手 / 自测**。路线层再加一个词：**接得上**。

不是一篇文章，不是一张漂亮网页，是一个**围绕具体学习目标设计的微型学习环境**。

---

## 1. 三条硬数据（先说清楚，改设计前先看）

这三条数字来自实测研究，不是我拍脑袋的偏好喵。

| 数字 | 出处 | 对设计的强制约束 |
|---|---|---|
| **特定生成流程的合格率 3.5% → 10 轮改进后 69.3%** | Kovshov et al., *Harnessing Generative UI for Education*, arXiv:2609.20738（Google Research；Gemini 生成流程） | **生成完必须自评再改**；10 轮是实验设置，不是每课硬指标。见 C2 |
| **研究中 Guided 对低先验学习者更有帮助，Buggy 对高先验学习者更有帮助** | Tithi et al., *Exploring the Design and Impact of Interactive Worked Examples for Learners with Varying Prior Knowledge*, arXiv:2602.16806 | **先判先验档位，再选择合适练习形态**。见 C3；结果来自逻辑问题辅导实验，不保证适用于所有主题 |
| **答案对 + 推理错，微调分类器只查出 57%；推理模型查出 84% 但假阳性 18%（约 8:1）** | Imran & Bulathwela, *The Correct Answer Trap*, arXiv:2606.23205 | **只看答案对错 = 会在强化误解**。见 C5 |

外加两条：**无引导的纯发现学习基本无效**（Kirschner, Sweller & Clark, 2006）；**只给结论不给推导会制造「理解错觉」**（Hörnlein & Kulgemeyer, 2025, arXiv:2512.02824）。

## 2. 八条不可妥协条款

改流程前先逐条对照。踩任何一条，这节课就不合格喵。

| # | 条款 | 破了会怎样 |
|---|---|---|
| **C1** | **目标必须可验证**：「能做什么」而不是「了解什么」 | 无法检查，练习与讲解脱钩 |
| **C2** | **生成后必须自评迭代**：教学、交互、体验三类检查各至少一轮；发现即修，连续一轮无新问题可停，不机械凑 10 轮 | 单次生成合格率只有 3.5% |
| **C3** | **先判先验档位，再定讲解深度与练习形态** | 给零基础讲矩阵乘向量 = 第一段流失；给行家补基础 = 灌水 |
| **C4** | **每个结论前必须有推论链**（现象→为什么→所以→不这样会怎样） | 读者「觉得懂了」，自测题前空手 |
| **C5** | **练习必须能区分「答案对」和「方法对」** | 用错误推理蒙对答案，系统不但没纠正，还确认了误解 |
| **C6** | **演示必须真算数，禁止写死的假数字** | 用户一乱填就露馅；假动画教出的是「看起来对」 |
| **C7** | **必须声明检查了什么、没检查什么** | 把「静态检查通过」说成「验证通过」= 谎报 |
| **C8** | **交互必须闭环**：用户操作 → 状态变化 → 结果反馈 → 原理解释；做不到就降级成表格 | 点一下播动画只是观看，不是学习 |

补充要求（来自现有工程经验，同样不可省）：**单文件、零外部请求、断网双击能打开**。

## 3. 工作流（七步，按序）

详细执行细则见 `references/teaching-workflow.md`。

### Step 1 · 判先验档位
三档，问一次即可，或从上下文推断：

| 档位 | 特征 | 讲解深度 | 练习形态（C3） |
|---|---|---|---|
| **零基础** | 不知道矩阵、向量、函数 | 每个术语都拆，多用日常类比 | **Guided**：给半成品，让填缺口 |
| **有编程/工具基础** | 会写代码，不懂这个领域 | 术语可少拆，直接用代码演示 | **Guided 偏难**：改参数预测结果 |
| **有领域基础** | 只缺这一块 | 直接上卡点，砍掉铺垫 | **Buggy**：给错误解法，让找错修错 |

**为什么这样选**：该研究中，Guided 让低先验学习者更多求助、更少犯错；Buggy 对高先验学习者更有帮助。把它当作选型依据，而不是跨主题都成立的定律；若用户反馈显示练习太难或太简单，应调整形式。

### Step 2 · 定锚：写一句可验证的目标
「能在纸上手算 3 个词的注意力权重，且每行加起来是 1」✅
「理解注意力机制」❌

这句话直接决定 Step 6 的题和 Step 7 的动手题。写成什么样，课就长成什么样。

### Step 3 · 列卡点，不是列知识点
**全流程最容易做错的一步。** 对每个待讲概念问三句：
1. 他读到哪一句会停住？
2. 停住是因为缺哪个前置概念？
3. 那个前置他能自己推出来吗？不能就先给。

输出成表，见 `references/teaching-workflow.md#卡点清单模板`。

### Step 4 · 设计交互
先判断知识适不适合可视化，再选演示形式。**五个问题必须答得出来**，答不上就退成一张好表格：

1. **哪些知识适合可视化？** 有对象、有关系、有中间状态、有可调参数的适合；纯定义、纯结论、无可观察变化的不适合。
2. **用户可以操作什么？** 拖拽、点击、输入、调参、单步、暂停、重置。操作必须对应真实变量。
3. **操作会改变什么？** 必须能说清「改了 X，所以 Y 变了」。说不清就是装饰。
4. **如何反馈变化？** 用真实计算出的数值、图形或中间量，不用预设动画冒充结果。
5. **如何通过操作验证理解？** 先预测再操作，或给一个必须动手才能完成的任务。

核心闭环（缺一环就降级）：

```
预测 → 用户操作 → 状态变化 → 结果反馈 → 原理解释 → 迁移
```

五个原则：**对象化呈现 / 动态过程 / 主动操作 / 即时反馈 / 原理解释**。参考范式是 Sort Playground，但只借范式，不搬它的排序算法、页面布局或视觉皮肤。

演示优先级：**真算的计算器 > 可拖的滑块 > 可点开的分步走 > 静态对照表**。判断标准一句话：**用户乱填时它还能给出对的答案**。做不到就别硬做演示，改成一张好表格。五问细则与对照表见 `references/interaction-patterns.md`。

### Step 5 · 写推导四句
```
[现象]   你会看到 X。
[为什么] 因为 A → B → C。
[所以]   于是就有了 Y 这个做法。
[不这样] 假如不这么做，会变成 Z（通常更糟）。
```
四句缺一不可，**最后一句「反例」最常被漏，但它才是让人记住的原因**。

### Step 6 · 出自测
- 每 1~2 个概念 1 题，总数 6~10
- 每题 3~4 个选项，**错误选项必须是真实的常见误解**，不能凑数（C5）
- **答完才展开要点**：答错自动展开，答对只给一行确认
- 至少 1 题是迁移题（换没讲过的新情境）
- 允许「我答对了但心里没底」这种状态：讲解只能给到「方法对不对」，答对不等于掌握

### Step 7 · 自评迭代 + 收尾
按三类检查各过一遍（**每轮只查一类，发现就修；不机械凑 10 轮**）：

| 检查 | 查什么 | 对应维度 |
|---|---|---|
| **教学检查** | 内容准确、推导合理、目标匹配、术语已拆、难度递进 | Factuality / Alignment / Clarity / Progression |
| **交互检查** | 状态真实、计算正确、操作有效、反馈闭环、可重复/暂停/重置 | Solution / Telemetry / Mechanical |
| **体验检查** | 视觉清晰、布局合理、操作流畅、手机可读、深浅色正常 | Visual |

- 三类各至少一轮；连续一轮找不出新问题就停。
- **每轮必须落到具体维度**：发现问题写修法，没问题写「已确认哪一条」，不重复空转。
- 没做真实浏览器测试的交互，必须标注「未实测」，不能写成已验证（C7）。

然后：动手题 + 完成清单 + 下一站预告。
**没检查的项必须写进 README，不许含糊**（C7）。

## 4. 输出规范

### 4.1 文件形态
```
lesson/                      # 单节课
├── index.html
└── README.md

route/                       # 学习路线
├── route.html               # 汇总页（驾驶舱）：终点 / 进度 / 今天该学 / 路线图 / 依赖 / 边界
├── day-01.html … day-NN.html # 每天一节独立课程，单独打开也完整
└── README.md
```
- `index.html` / `day-NN.html` 都是可独立打开的单文件课程；`route.html` 同理；`README.md` 写清学习目标、打开方式、依赖、验证结果、已知限制和自评迭代记录。
- 双击就能打开，零外部请求（不引 CDN / 在线字体 / 外链图片 / 框架）
- 视觉风格主题自适应，不固定为某一种皮肤；视觉服务于教学，不要让所有课程长得一样
- 同时提供 Day Mode / Dark Mode，两套主题下都清晰可读
- 视觉技术按需选择 CSS / SVG / Canvas / Three.js：Three.js 不是强制项，只在三维空间关系确实需要时使用；不为技术效果增加不必要的依赖

| 课程类型 | 视觉方向 |
|---|---|
| 技术课程 | 工程笔记、代码实验室 |
| 数学物理 | 动态实验室、数据可视化 |
| 艺术设计 | 画布、空间探索 |
| 算法课程 | 角色化、游戏化交互 |

### 4.2 页面骨架（按顺序）
1. 顶部一句话：这节课学完你能做什么
2. 前置检查（可折叠）：确认必要基础，给补充入口
3. 主干分「站」：每站 = 一个卡点 + 一个交互（或对照表）+ 推导四句；交互须走完「操作→状态→反馈→解释」
4. 自测：6~10 题，答完才展开
5. 动手：可复制代码 / 可操作练习 + 预期输出
6. 完成清单
7. 明天预告 + 今天没讲什么（属于路线时）；路线第一天不需要回指块

路线汇总页则是六块：**终点 / 进度 / 今天该学 / 路线图 / 依赖 / 边界**。详见 `references/learning-route.md`。
7. 来源与边界：资料依据、简化假设、已知限制
8. 下一站预告 + 速查卡（默认折叠）

### 4.3 字数预算

| 档位 | 阅读量 | 演示数 | 自测题 |
|---|---|---|---|
| 零基础 | 4000~6000 字 | 5~7 | 8~10 |
| 有编程基础 | 2500~4000 字 | 3~5 | 6~8 |
| 有领域基础 | 1500~2500 字 | 2~3 | 4~6 |

超预算不是「讲得细」，是没砍干净喵。

## 5. 交付前自检

先跑脚本，再过人工清单：

```bash
node scripts/validate-lesson.mjs <课程.html>     # 静态断言，18 项
node scripts/audit-page.mjs <课程.html>          # 真浏览器审计，6 项
```

静态跑完先过一遍；再跑浏览器审计，它会真的点开练习、真的在 320px 下排版。两个分开是因为静态检查不需要浏览器，而浏览器审计需要 Playwright。校验项见 `references/audit-page.md`。

- [ ] 目标可验证，且与练习对应（C1）
- [ ] 已做教学 / 交互 / 体验三类自评各至少 1 轮（C2）
- [ ] 先验档位已判，练习形态与之匹配（C3）
- [ ] 每个结论前面都有推导四句（C4）
- [ ] 干扰项都对应真实误解，不是凑数（C5）
- [ ] 演示乱填不崩、答案对（C6）
- [ ] 每个交互都走完「操作 → 状态变化 → 反馈 → 解释」闭环（C8）
- [ ] 交互实测：可重复、可暂停、可重置，极端输入不报错
- [ ] 数据与动画同步，不是预设的假结果
- [ ] 手机宽度下布局、触控和文字正常
- [ ] 深色 / 浅色两套主题都能正常阅读
- [ ] 有至少一道迁移题
- [ ] 断网双击能打开，页面零外部请求
- [ ] README 写清了「已检查 / 未检查」（C7）

逐项细则见 `references/quality-checklist.md`。

## 6. 能力缺失时的降级规则

**不要把「没做」说成「做完了」**，见 C7。

| 缺什么 | 降级做法 | 必须写进交付说明 |
|---|---|---|
| 联网检索 | 只用参数化知识，不编造引用 | 「未联网核验」 |
| 浏览器测试 | 跑静态脚本，人工过一遍代码 | 「交互未实测」 |
| 代码执行 | 给代码 + 预期输出，说明未运行 | 「代码未实际运行」 |
| 专属预览环境 | 交付普通浏览器可打开的文件 | 「无专属预览」 |
| 持久化记忆 | 靠课程文件 + 用户反馈继续 | 「不记得历史」 |

## 7. 明确不做

- ❌ 知识点罗列式目录（那是大纲，不是课）
- ❌ 只有结论没有推导
- ❌ 假动画 / 写死的假数字 / 摆拍的热力图
- ❌ 自测题直接展示答案
- ❌ 引 CDN / 框架 / 在线字体 / 外链图
- ❌ 只能自动播放、用户插不上手的演示（本仓的 `▶ 看一遍演示` 可随时点停、随时接管，不算）
- ❌ 为视觉效果强行引入 3D 或额外依赖
- ❌ 一页塞完所有细节
- ❌ 面向行家补基础铺垫
- ❌ 用分数 / 连击 / 排行榜做激励（把学习变成刷分）
- ❌ 把「页面上答对选择题」说成「已经掌握这门技能」
