# knowvori · 交互式学习

## 0. 一句话定位

> **说出你想学什么，拿到一节能动手探索、通过练习检查理解的交互课程。**

三个词：**卡点 / 动手 / 自测**。

不是一篇文章，不是一张漂亮网页，是一个**围绕具体学习目标设计的微型学习环境**。

---

## 1. 三条硬数据（先说清楚，改设计前先看）

这三条数字来自实测研究，不是我拍脑袋的偏好喵。

| 数字 | 出处 | 对设计的强制约束 |
|---|---|---|
| **单次生成合格率 3.5% → 10 轮自评迭代后 69.3%** | Kovshov et al., *Harnessing Generative UI for Education*, arXiv:2609.20738 (Google Research) | **生成完必须自评再改，一轮不算完**。见 C2 |
| **低先验知识者要 Guided（填空），高先验知识者要 Buggy（找错）** | Tithi et al., *Interactive Worked Examples*, arXiv:2602.16806 (CHI'26) | **先判先验档位，再选练习形态**。见 C3 |
| **答案对 + 推理错，微调分类器只查出 57%；推理模型查出 84% 但假阳性 18%（约 8:1）** | Imran & Bulathwela, *The Correct Answer Trap*, arXiv:2606.23205 | **只看答案对错 = 会在强化误解**。见 C5 |

外加两条：**无引导的纯发现学习基本无效**（Kirschner, Sweller & Clark, 2006）；**只给结论不给推导会制造「理解错觉」**（Hörnlein & Kulgemeyer, 2025, arXiv:2512.02824）。

## 2. 七条不可妥协条款

改流程前先逐条对照。踩任何一条，这节课就不合格喵。

| # | 条款 | 破了会怎样 |
|---|---|---|
| **C1** | **目标必须可验证**：「能做什么」而不是「了解什么」 | 无法检查，练习与讲解脱钩 |
| **C2** | **生成后必须自评迭代，至少 3 轮**（理想 10 轮），每轮换视角找缺陷 | 3.5% 合格率就是这么来的 |
| **C3** | **先判先验档位，再定讲解深度与练习形态** | 给零基础讲矩阵乘向量 = 第一段流失；给行家补基础 = 灌水 |
| **C4** | **每个结论前必须有推论链**（现象→为什么→所以→不这样会怎样） | 读者「觉得懂了」，自测题前空手 |
| **C5** | **练习必须能区分「答案对」和「方法对」** | 用错误推理蒙对答案，系统不但没纠正，还确认了误解 |
| **C6** | **演示必须真算数，禁止写死的假数字** | 用户一乱填就露馅；假动画教出的是「看起来对」 |
| **C7** | **必须声明检查了什么、没检查什么** | 把「静态检查通过」说成「验证通过」= 谎报 |

补充要求（来自现有工程经验，同样不可省）：**单文件、零外部请求、断网双击能打开**。

## 3. 工作流（七步，按序）

详细执行细则见 `references/teaching-workflow.md`。

### Step 1 · 判先验档位
三档，问一次即可，或从上下文推断：

| 档位 | 特征 | 讲解深度 | 练习形态（C3） |
|---|---|---|---|
| **零基础** | 不知道矩阵、向量、函数 | 每个术语都拆，多用日常类比 | **Guided**：给半成品，让填缺口 |
| **有编程/工具基础** | 会写代码，不懂这个领域 | 术语可少拆，直接用代码演示 | **Guided 偏难**：改参数预测结果 |
| **有领域基础** | 只缺这一块 | 直接上卡点，砍掉铺垫 | **Buggy**：给错误解法，让找错修错 |

**为什么这么配**：Guided 让学生更多求助、更少犯错，适合缺 schema 的人；Buggy 需要「知道对的长什么样」才能看出错，反而适合有基础的人。配反了不是效果打折，是效果归零。

### Step 2 · 定锚：写一句可验证的目标
「能在纸上手算 3 个词的注意力权重，且每行加起来是 1」✅
「理解注意力机制」❌

这句话直接决定 Step 6 的题和 Step 7 的动手题。写成什么样，课就长成什么样。

### Step 3 · 列卡点，不是列知识点
**全流程最容易做错的一步。** 对每个待讲概念问三句：
1. 他读到哪一句会停住？
2. 停住是因为缺哪个前置概念？
3. 那个前置他能自己推出来吗？不能就先给。

输出成表，见 `references/teaching-workflow.md#卡点清单模板`。

### Step 4 · 选演示
优先级：**真算的计算器 > 可拖的滑块 > 可点开的分步走 > 静态对照表**。
判断标准一句话：**用户乱填时它还能给出对的答案**。做不到就别硬做演示，改成一张好表格。对照表见 `references/interaction-patterns.md`。

### Step 5 · 写推导四句
```
[现象]   你会看到 X。
[为什么] 因为 A → B → C。
[所以]   于是就有了 Y 这个做法。
[不这样] 假如不这么做，会变成 Z（通常更糟）。
```
四句缺一不可，**最后一句「反例」最常被漏，但它才是让人记住的原因**。

### Step 6 · 出自测
- 每 1~2 个概念 1 题，总数 6~10
- 每题 3~4 个选项，**错误选项必须是真实的常见误解**，不能凑数（C5）
- **答完才展开要点**：答错自动展开，答对只给一行确认
- 至少 1 题是迁移题（换没讲过的新情境）
- 允许「我答对了但心里没底」这种状态：讲解只能给到「方法对不对」，答对不等于掌握

### Step 7 · 自评迭代 + 收尾
按四类 critique 各过一遍（**至少 3 轮，每轮换视角**）：

| critique 类别 | 查什么 |
|---|---|
| **Visual** | 格子溢出、手机上挤不挤、深色下读不清、动画抢注意力 |
| **Solution** | 演示的数值对不对？乱填会不会崩？目标能不能达成？ |
| **Telemetry** | 用户能看到自己操作的结果吗？中间量有没有暴露？ |
| **Mechanical** | 外部请求、报错、按钮无响应、状态回不去 |

然后：动手题 + 完成清单 + 下一站预告。
**没检查的项必须写进 README，不许含糊**（C7）。

## 4. 输出规范

### 4.1 文件形态
```
<课程目录>/<主题>-<档位>.html
```
- 单文件、零外部请求（不引 CDN / 在线字体 / 外链图片 / 框架）
- 视觉走「纸质工程笔记」：米底、墨黑、一个强调色。避开大渐变 + 发光字
- 双击就能打开

### 4.2 页面骨架（按顺序）
1. 顶部一句话：这节课学完你能做什么
2. 前置检查（可折叠）：确认必要基础，给补充入口
3. 主干分「站」：每站 = 一个卡点 + 一个演示 + 推导四句
4. 自测：6~10 题，答完才展开
5. 动手：可复制代码 / 可操作练习 + 预期输出
6. 完成清单
7. 来源与边界：资料依据、简化假设、已知限制
8. 下一站预告 + 速查卡（默认折叠）

### 4.3 字数预算

| 档位 | 阅读量 | 演示数 | 自测题 |
|---|---|---|---|
| 零基础 | 4000~6000 字 | 5~7 | 8~10 |
| 有编程基础 | 2500~4000 字 | 3~5 | 6~8 |
| 有领域基础 | 1500~2500 字 | 2~3 | 4~6 |

超预算不是「讲得细」，是没砍干净喵。

## 5. 交付前自检

先跑脚本，再过人工清单：

```bash
node scripts/validate-lesson.mjs <课程.html>
```

- [ ] 目标可验证，且与练习对应（C1）
- [ ] 已做至少 3 轮自评迭代（C2）
- [ ] 先验档位已判，练习形态与之匹配（C3）
- [ ] 每个结论前面都有推导四句（C4）
- [ ] 干扰项都对应真实误解，不是凑数（C5）
- [ ] 演示乱填不崩、答案对（C6）
- [ ] 有至少一道迁移题
- [ ] 断网双击能打开，页面零外部请求
- [ ] README 写清了「已检查 / 未检查」（C7）

逐项细则见 `references/quality-checklist.md`。

## 6. 能力缺失时的降级规则

**不要把「没做」说成「做完了」**，见 C7。

| 缺什么 | 降级做法 | 必须写进交付说明 |
|---|---|---|
| 联网检索 | 只用参数化知识，不编造引用 | 「未联网核验」 |
| 浏览器测试 | 跑静态脚本，人工过一遍代码 | 「交互未实测」 |
| 代码执行 | 给代码 + 预期输出，说明未运行 | 「代码未实际运行」 |
| 专属预览环境 | 交付普通浏览器可打开的文件 | 「无专属预览」 |
| 持久化记忆 | 靠课程文件 + 用户反馈继续 | 「不记得历史」 |

---

## 7. 明确不做

- ❌ 知识点罗列式目录（那是大纲，不是课）
- ❌ 只有结论没有推导
- ❌ 假动画 / 写死的假数字 / 摆拍的热力图
- ❌ 自测题直接展示答案
- ❌ 引 CDN / 框架 / 在线字体 / 外链图
- ❌ 一页塞完所有细节
- ❌ 面向行家补基础铺垫
- ❌ 用分数 / 连击 / 排行榜做激励（把学习变成刷分）
- ❌ 把「页面上答对选择题」说成「已经掌握这门技能」
